# Результат F5 · приватный виджет amoCRM · 0.2.2

Версия 0.2.2 убирает демоданные и читает API **текущего аккаунта**, в котором открыт виджет. В продуктовых файлах нет генератора случайных сделок, фиксированных показателей или переключения на демо при ошибке. Без доступа к API отчёт останавливается.

## Установка

Загрузите `dist/result-f5-0.2.2.zip` вместо прежнего ZIP в приватную интеграцию, сохраните обновление и полностью перезагрузите amoCRM. Кнопка «Результат F5» в левом меню открывает расширенные настройки виджета. Укажите настоящую дату внедрения; кнопка «До 28 завершённых дней» заполняет равные периоды из уже прошедших дней (от 1 до 28). Можно изменить обе пары дат. Будущие и незавершённые дни не сравниваются.

Аккаунт, его ID и часовой пояс видны в отчёте. Данные загружаются автоматически; «Обновить данные аккаунта» повторяет загрузку. После изменения дат нажмите «Рассчитать по событиям». Названия воронок, менеджеров и источников получаются из аккаунта; при недоступном справочнике отображаются реальные ID.

## Что считается

- **Новые сделки**: доступные неудалённые карточки с created_at в периоде. Полная пагинация доступных карточек не включает навсегда удалённые или скрытые правами записи.
- **Успешные сделки**: уникальные сделки с доступным событием lead_status_changed из другого этапа в системный успешный статус 142 в периоде. Повторные успехи одной сделки внутри периода считаются один раз. Это не первый успех за всё время и не гарантия полноты старого журнала.
- **До наблюдаемого успеха**: среднее от создания до самого раннего доступного успешного перехода в выбранном периоде для каждой такой сделки. Не подменяется текущим closed_at. Если даты создания части выборки недоступны, среднее не показано.
- **Сейчас, отдельный блок**: просроченные незавершённые задачи сделок и активные сделки без доступной незавершённой задачи. Они не подставляются в исторические карточки. Просроченная задача тоже считается следующей.

Историческая сумма успешных сделок, конверсия когорты за 28 суток, исторические просроченные задачи и активные без следующей задачи пока показывают **«Недостаточно исторических данных»**. Виджет не восстанавливает старые бюджеты/задачи из текущего состояния и не вычисляет ложную конверсию отношением успешных к новым. В карточках доступны формулы и причины; ссылки открывают настоящие ID сделок текущего аккаунта.

Фильтры обозначены как **текущие**: воронка, ответственный сделки, источник сейчас. Это сегмент текущих доступных карточек, не восстановление прошлых назначений. События без доступной карточки включаются только без фильтров. Права пользователя ограничивают данные; для анализа всего доступного аккаунта проверяйте виджет под администратором. Одинаковые периоды не доказывают одинаковое покрытие историей. Недельные количества успешных сделок не всегда складываются в итог периода: одна сделка может иметь успехи в нескольких неделях.

## Без сервера

Используются относительные GET-запросы /api/v4 в текущей сессии amoCRM. Сервер интеграции, OAuth-обмен, токены в ZIP или хранилище браузера отсутствуют. Работу сессионной авторизации ещё необходимо подтвердить в целевом аккаунте. При 401/403 нет обхода или подстановки чисел: виджет показывает ошибку. Если amoCRM не разрешит этот способ чтения в аккаунте, потребуется отдельно решить безопасное подключение, не помещая client_secret/refresh_token в клиентский код.

История и текущая выборка хранятся только в памяти страницы. На выгрузке проверяются account_id и ссылки пагинации: переход на другой origin запрещён. Запросы последовательные, максимум около 2,5/сек, 429/502/503/504 повторяются ограниченно с ожиданием; отмена и ошибки неполной пагинации не дают частичных итогов. При закрытом виджете сбор и регулярные снимки не работают. Данные API могут изменяться во время выгрузки; она не атомарная, показаны начало и окончание чтения.

Штатный left_menu/widget_page по официальной документации доступен только публичным интеграциям с техническим аккаунтом. Для приватного ZIP используется UI-ссылка в #nav_menu. При изменении DOM платформы этот адаптер может потребовать обновления.

## Разработка и проверки

Нужны Node.js 18+ и Python 3. Зависимости приложения отсутствуют.

```sh
npm test
npm run package
npm start
```

Локальная index.html без контекста amoCRM показывает отсутствие подключения, **не демо**. Для автоматической браузерной проверки предусмотрен `python scripts/check-browser.py` при запущенном npm start; отдельно нужны Playwright и Chromium. Ответы CRM в этом тесте — явно тестовые заглушки, не часть ZIP и не подключение клиента.

[Матрица API](docs/availability.md) · [Результаты проверок](docs/validation.md).

В 0.2.2 недавнее внедрение больше не создаёт будущий период: при внедрении 06.10.2026 и текущей дате 13.10.2026 сравниваются 29.09–05.10 и 06.10–12.10 (7 дней). После выбора даты автоматический расчёт запускается сразу. Все семь карточек видны и при ошибке выбора дат: значения заменяются прочерками с объяснением, а не скрываются целиком.

В 0.2.2 все кнопки имеют type=button для работы внутри формы amoCRM. При нажатии автовыбора или расчёта без даты появляется явная подсказка, а фокус переходит к дате внедрения.
